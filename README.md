# yamDetector

Sound-awareness system. A room unit (Seeed XIAO ESP32S3 Sense with 4 PDM MEMS mics)
classifies **siren / car_horn / alarm / knock** on the device and stays quiet on
everything else (**background**). An ESP-01 wristband with a vibration motor and an
OLED will receive alerts over ESP-NOW.

| Working | Not built yet |
| --- | --- |
| 4-mic capture, 0 dropped blocks | ESP-NOW alerts to the wristband |
| Recording training clips to the laptop | Direction estimate from the mic array |
| On-device int8 classifier printing to Serial | |

The model is a small DS-CNN trained with TensorFlow/Keras on ESC-50 plus our own
recordings, exported to int8 TFLite Micro.

## Layout

```
room_capture/            room unit firmware (capture, level meters, stream, on-device inference)
  yam_infer.h            classifier: feature pipeline + TFLite Micro + event logic
  model.h                generated by export.py, committed so the sketch builds
bringup/                 board bring-up sketches: print MAC, PSRAM / supply voltage, msg_t size
libraries/protocol/      protocol.h: shared constants, radio message, class list
libraries/microfrontend/ TensorFlow audio microfrontend C code (the on-device feature extractor)
host/recorder.py         records the room unit's stream into my_recordings_raw/<label>/

config.yaml              every ML setting (classes, audio, features, splits, training)
scripts/                 stage 1 prepare_esc50.py, stage 2 convert_recordings.py
train.py, export.py      stage 3 train, stage 4 export (TFLite, model.h, labels.txt)
src/yamdetector/         shared Python library (audio, manifest, features, model, metrics)
tests/                   unit tests for slicing and split logic
data/ESC-50/             the ESC-50 dataset (read-only, CC BY-NC: see data/ESC-50/LICENSE)
```

Generated and gitignored: `data/processed/`, `data/features/`, `artifacts/`,
`my_recordings_raw/` (share recordings through a drive).

## 1. Wiring

Room unit, XIAO ESP32S3 Sense:

| Signal | XIAO pin | Mics |
| --- | --- | --- |
| PDM clock | D0 (GPIO1) | all four, shared |
| PDM data 0 | D1 (GPIO2) | mics 1 and 2 |
| PDM data 1 | D3 (GPIO4) | mics 3 and 4 |
| SEL | GND for mics 1 and 3, 3V3 for mics 2 and 4 | |
| VCC / GND | 3V3 / GND | all |

Avoid D2 (strapping pin) and D8-D10 (used by the Sense's SD slot). The classifier listens to mic 1.

Wristband, ESP-01 (planned): 3.3 V only (2x AA, no regulator, never 5 V). OLED SDA on GPIO0,
SCL on GPIO2. Motor on GPIO3 through an NPN transistor. Flash it through an ESP32 DevKit V1: see
the header of `bringup/esp01_hello/esp01_hello.ino`.

## 2. Setup

**Python** (CPU works everywhere):

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1          # Git Bash: source .venv/Scripts/activate
pip install -r requirements.txt
```

TensorFlow has no GPU support on native Windows. To train on the GPU, use WSL2 with
`pip install "tensorflow[and-cuda]>=2.16" -r requirements.txt`. `train.py` prints which device
it picked and falls back to CPU.

**Arduino IDE:**

1. Boards Manager: install **esp32 by Espressif Systems** 3.x (TFLite Micro ships with it).
   Add the **esp8266** core for the wristband.
2. **File > Preferences > Sketchbook location** = this repo folder, so every sketch finds
   `libraries/protocol` and `libraries/microfrontend`.
3. Tools for the room unit: Board **XIAO_ESP32S3**, USB CDC On Boot **Enabled**,
   PSRAM **OPI PSRAM**.

## 3. Train and export

```bash
python scripts/prepare_esc50.py                 # ESC-50 -> data/processed (folds 1-3 train, 4 val, 5 test)
python scripts/convert_recordings.py            # optional: adds my_recordings_raw/<class>/*
python train.py                                 # features are cached, reruns start fast
python export.py --firmware-dir room_capture    # artifacts/ + room_capture/model.h
```

Useful options:

```bash
python scripts/prepare_esc50.py --limit 50      # smoke test (splits will be incomplete)
python scripts/convert_recordings.py --mix      # average all channels (default: channel 0)
python scripts/convert_recordings.py --channel 1
python train.py --epochs 10 --batch-size 8      # quick experiment
python train.py --no-augment --force-features   # no augmentation, rebuild the feature cache
```

Every stage can be re-run safely. Stage 1 replaces only ESC-50 rows, stage 2 replaces only
its own rows, and stage 3 reuses cached features.

**Class order matters.** The model's output index is the class id the firmware uses.
`classes.order` in `config.yaml` must match `CLASS_NAMES` and the `CLS_` enum in
`libraries/protocol/protocol.h`. `export.py` warns on a mismatch, and `yam_infer.h` refuses
to compile if the class counts differ.

## 4. Run the room unit

Open `room_capture/room_capture.ino`, pick a `MODE` at the top, and upload.

| `MODE` | What it does | Watch with |
| --- | --- | --- |
| `MODE_LEVELS` | level meter per mic and the measured data rate | Serial Monitor |
| `MODE_STREAM` | binary audio stream for recording training clips | `host/recorder.py` (Serial Monitor closed) |
| `MODE_INFER` | on-device classifier | Serial Monitor (any baud, native USB) |

With new mics, bring them up in that order. In `MODE_LEVELS`, snap your fingers next to each
mic: only its meter should jump. If the wrong meter moves, fix `SLOT_FOR_MIC`.

Command-line upload:

```powershell
arduino-cli compile --upload -p COM11 --fqbn esp32:esp32:XIAO_ESP32S3:CDCOnBoot=default,PSRAM=opi --libraries libraries room_capture
```

`MODE_INFER` output:

```text
[yamDetector] ready: model 44928 B, arena used 52112 of 163840 B (internal RAM), threshold 0.70
siren 0.01  car_horn 0.02  alarm 0.01  knock 0.03  background 0.93  | gain 10.0 | 38 ms
siren 0.91  car_horn 0.04  alarm 0.03  knock 0.00  background 0.02  | gain  2.1 | 38 ms
[yamDetector] Event: SIREN | Conf: 91% | #1
```

- One line per window: 1 s of audio, every 0.5 s. `gain` is the peak-normalization boost, and
  the last number is the processing time.
- An **Event** line prints when the top class isn't background, its probability reaches
  `DETECT_THRESHOLD`, and that class hasn't fired within `COOLDOWN_MS`.
- These settings are at the top of `room_capture/yam_infer.h`. `PRINT_PROBS 0` leaves only
  the Event lines.
- Quick test: play ESC-50 fold-5 clips (siren, car_horn, clock_alarm, door_wood_knock) from a speaker.

## 5. Record your own training data

`recorder.py` saves mic 1 as channel 0, which is what `convert_recordings.py` uses by default,
so these clips match what the device hears.

1. Flash `room_capture` with `MODE_STREAM` and close the Serial Monitor.
2. Record each class, playing the sound from a phone at a few distances and angles:

   ```bash
   python host/recorder.py --port COM11 --label alarm --seconds 10
   python host/recorder.py --port COM11 --label background --seconds 60
   ```

   It prints the dropped-block count and the strongest frequency on mic 1.
3. `python scripts/convert_recordings.py`, then train and export.

Every folder in `my_recordings_raw/` becomes a class, so delete or move test takes before
converting. A new folder name adds a new class. Add it to `classes.order` and `protocol.h` to
fix its position. ESC-50's `clock_alarm` is not a smoke alarm, so record a real one into
`my_recordings_raw/alarm/`.

## How the pipeline works

```
data/ESC-50/       ── prepare_esc50.py ───────┐
                                              ├──► data/processed/<class>/*.wav + manifest.csv
my_recordings_raw/ ── convert_recordings.py ──┘                  │
                                                                 ├──► train.py  -> artifacts/model.keras
                                                                 └──► export.py -> model_int8.tflite, model.h, labels.txt
```

- **Manifest.** `manifest.csv` (`path,class,source,source_file_id,split`) is the only thing
  training reads, besides `config.yaml`. Splits are assigned per source recording, never per
  window, so one recording can't leak across train/val/test.
- **Windows.** 16 kHz mono, 1 s, peak-normalized to 0.95 (max +20 dB). Near-silent windows
  are skipped for target classes. Background is subsampled to 4x the average target class.
- **Features.** TensorFlow `audio_microfrontend`: 40 channels, 30 ms window, 20 ms step,
  125-7500 Hz, log + PCAN, divided by 255. This gives `49 x 40 x 1` per window, cached under
  `data/features/` as one `.npy` each.
- **Augmentation** (train split only): background noise at 0-20 dB SNR, gain of ±6 dB, and a
  time shift of ±100 ms. Copies are generated once and cached.
- **Model.** DS-CNN: a 3x3 conv stem and four depthwise-separable blocks (64 filters), then
  global average pooling and softmax. About 21k parameters, with ReLU6 and BatchNorm for clean
  int8 conversion.
- **Training.** Adam, square-root inverse-frequency class weights, and early stopping on
  `val_loss`. It reports per-class precision/recall, a confusion matrix
  (`artifacts/confusion_matrix.png`), and the **false-positive rate on background**.
- **Export.** Writes float and int8 TFLite, and warns if int8 accuracy drops by more than 3
  points. Also writes `model.h` (C array plus input scale and zero point) and `labels.txt`.

### Device / training contract

`yam_infer.h` reproduces training exactly. Change these together with the model:

1. Take 1 s of mic 1 at 16 kHz int16, after the DC blocker in `room_capture.ino`.
2. Peak-normalize it as `audio.peak_normalize` does (0.95, max +20 dB).
3. Run the microfrontend with the same parameters as `features.py`, and **reset its state for
   every window**. The Python op starts fresh, but the C frontend carries noise-reduction and
   gain state across frames.
4. Divide by `features.value_scale` (255). Quantize with
   `int8 = clip(round(f / kYamInputScale) + kYamInputZeroPoint)`, using the constants
   from `model.h`.

`libraries/microfrontend/` is the same C code the TensorFlow op runs, pinned to a TensorFlow
commit (see its `library.properties`).

## Troubleshooting

- **`audio_microfrontend op is unavailable`**: install the full `tensorflow` wheel, not a
  stripped build.
- **`could not find the ESC-50 dataset`**: the message lists every path it tried. Set
  `paths.esc50_*` in `config.yaml` or pass `--esc50-root`.
- **Stale features after editing `config.yaml`**: this can't happen, because the cache folder
  is keyed by the feature settings. Use `--force-features` to rebuild anyway.
- **Out of memory**: lower `training.batch_size` and `augment.noise_pool_size`.
- **`recorder.py` gets no frames**: the sketch isn't in `MODE_STREAM`, or the Serial Monitor
  still holds the port.
- **Fast-blinking LED on the room unit**: the PDM driver failed to start. Check pins and settings.
